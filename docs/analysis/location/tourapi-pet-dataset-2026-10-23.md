# 반려동물 동반 장소 데이터 공급 — TourAPI 실측 (2026-10-23)

> 커밋 `f72fd6d7` 기준. 측정일 2026-10-23. 개발 DB `petory`(24,130행) 와 대조했다.
>

## 2. 왜 다른 경로를 포기했는가 (2026-10-22~23)

| 경로 | 판정 | 근거 |
|---|---|---|
| 네이버플레이스·카카오맵 **크롤링** | ⛔ 불가 | robots.txt + 이용약관 금지 |
| **카카오 로컬 API** 결과 DB 적재 | ⛔ 불가 | 카카오 측 데브톡 답변: *"저장 방식은 현재 정책상 금지하고 있는 사항에 해당"*, *"모든 정보는 사용자에게 제공될 때마다 매번 실시간으로 호출하여야 한다"*. 질문자가 「한정된 자체 콘텐츠용 백필」을 물었고 그것도 금지로 답했다 |
| **네이버 검색/지도 API** 적재 | ⛔ 불가 | 2026-09 약관 개정 — 복사·저장·캐싱 금지, 제3자 제공·별도 수익 금지 |
| **공공데이터** | ✅ 가능 | 이용허락범위 **제한 없음** |

📌 **다시 카카오·네이버 수집을 제안하지 말 것.** 저장이 금지이므로 설계가 성립하지 않는다.

## 3. API 실체

| 항목 | 값 |
|---|---|
| 데이터셋 | **한국관광공사_반려동물_동반여행_서비스** (`data.go.kr` **15135102**) |
| 엔드포인트 | `https://apis.data.go.kr/B551011/KorPetTourService2` |
| 이용허락범위 | **제한 없음** · 무료 · 실시간 갱신 |
| 동작 확인한 오퍼레이션 | `areaBasedList2`(9,660) · `locationBasedList2`(서울시청 20km → 42) · `searchKeyword2`("카페" → 19) · `areaCode2`(17) · `detailPetTour2` |

✅ **목록 오퍼레이션이 있다 → 일일 한도 문제가 없다.** 장소마다 `detailPetTour2` 를 부르면
개발계정 1,000회/일에 걸리는데, `areaBasedList2` 로 한 번에 받으면 5종 × 10페이지 = 수십 회로 끝난다.

⚠️ **키는 「인코딩」과 「디코딩」 두 형태가 있다.** 기존 `PublicDataApiClient` 는 **디코딩 키**를 받아
`URLEncoder` 로 직접 인코딩한다(`+` → `%2B`). 인코딩 키를 그대로 넣으면 **이중 인코딩**된다.

## 6. 🔴 지역 쏠림 — 이게 가장 중요하다

```
강원 210(24%) · 경기 107 · 전남광주 84 · 경북 67 · 서울 63 · 경남 55 · 울산 51 · ...

수도권(서울·경기·인천) = 205건 / 876건 (23%)
  └ 관광지 143 · 음식점 25 · 숙박 24 · 레포츠 11 · 문화시설 2
```

→ **수도권 사용자의 첫 화면에 새로 뜨는 건 205건, 그중 음식점·카페 25건이다.** 적다.
`locationBasedList2` 로 서울시청 20km 를 직접 조회해도 **42건**이다(전 카테고리 합).

**그래도 넣을 이유 두 개**
1. **종류가 다르다.** 수도권 음식점 25건만으로 현재 DB 의 **전국** 식당 21건을 넘는다
2. **`acmpyTypeCd` 가 100% 채워져 있다** — 표본 25건에서 「전구역 동반가능」 14 · 「일부구역 동반가능」 10 ·
   빈값 1. **기존 DB 에 없는 구분**이고 사용자가 실제로 알고 싶은 정보다

⚠️ **나머지 상세 필드는 거의 비었다** — `etcAcmpyInfo` 가 15건 중 1건. 타 프로젝트가 보고한
「`acmpyPsblCpam` 결측률 98%」가 대체로 맞았다. **`acmpyTypeCd` 하나만 믿을 수 있다.**

## 7. 🔴 적재 전 선행조건 — sido 정규화

TourAPI 의 시도명이 이렇게 들어온다:

```
전남광주통합특별시 84              ← 비표준
강원특별자치도 210                ← DB 는 「강원도」로 들고 있다
경기 2 · 서울 1 · 울산 1 · 전북 1 · 부산 1 · 경남 1 · 대구 1 · 인천 1   ← 약식
```

`SpringDataJpaLocationServiceRepository.findBySido` 가 `WHERE sido = :sido` **정확일치**다.
지금도 DB 안에 불일치가 있다 — 「서울특별시」 4,403 vs 「서울」 34(`PET_DATA_API` 출처),
부산 1,463 vs 9, 인천 1,354 vs 7. **53행(0.2%)이라 안 보이는 것이고 고쳐진 게 아니다.**

→ **이번 적재로 100건 넘게 늘어난다. 정규화를 먼저 해야 한다.**
(행정구역명도 낡았다 — DB 의 「강원도」884·「전라북도」902 는 각각 2023·2024 에 특별자치도로 바뀌었다.)

## 부록 — 「자주 찾는」은 이 데이터로 만들 수 없다
